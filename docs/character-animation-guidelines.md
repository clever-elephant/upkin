# 角色动画：项目约定与验收基线

通用设计规则、制作流程和验收方法以项目技能 [menu-bar-character](../.agents/skills/menu-bar-character/SKILL.md) 为统一入口。技能不绑定角色；复制整个技能目录可在其他项目复用。当前仓库的具体源码、参数和命令见 [项目适配参考](../.agents/skills/menu-bar-character/references/upkin.md)。

**已确认的体验原则：动作持续，表情稳定；一轮完整主动作只在一个固定节点换一次表情。**

一轮不是一次按键、一次踏步或半次转身。眼睛与嘴巴作为完整姿态同步变化；没有嘴巴的角色不新增嘴巴。轮内肢体可持续运动，但不触发额外换脸。真实等待、完成、错误仍即时响应，相同业务状态刷新不重播。

## 跨角色、跨状态的统一节奏规范

本规范适用于全部现有及新增角色、全部状态，不按角色各定一套频率。统一的是时间轴和状态语义，不是把造型与动作画成一样。

- **共同主节拍为4秒（15FPS下60帧）**，沿用 Grok 角色的工作主周期。待机、思考、工作、等待、未知/待确认的完整主动作按该节拍编排；跨状态保持一致的动作频率，不因角色不同忽快忽慢。
- **主节拍与素材循环分开**：A/B两轮表情或左右两次注视构成8秒/120帧素材循环，每个4秒主节拍的动作结构、切换节点与停留比例应一致。相同帧数或相同FPS本身不证明动作频率一致；动作内部也要检查，避免一包中塞入数量不同的重复动作。
- **面部统一规则**：工作有替代表情时仅在每轮起点同步切换一次；待机保持中性，思考在一次注视内保持同一表情，等待保持提示脸。没有替代表情时保持原脸；不为追求数字一致强加换脸、眨眼或新动作。眨眼使用相同的低频规则，禁止连续双眨及随机符号轮播。
- **各状态表达不同，节奏标准相同**：可以分别呼吸、注视、打字或提示，但起势、持续、回位与停留应按共同节拍组织。身体、面部与附件使用同一闭合时间轴；不只调整整个文件播放速度来掩盖内部节奏不一致。
- **完成/错误是事件动画，不强制循环**：同一状态的入场、表情稳定节点及单次时长应跨角色统一；随后按业务生命周期保持终帧或切换。真实状态更新始终即时响应，不等4秒节拍结束。
- **统一验收**：全部角色以同一状态并排播放，再检查每个角色跨状态切换；至少观察三轮主动作和两次素材接缝，记录主动作次数、面部切换时刻及眨眼次数。参数、源动作、导出帧和原生播放都达标后才记为节奏统一。

以下表格记录的是既有实现，不是各角色可保留不同频率的例外。历史单角色验收不等于符合本次统一节奏规范；保护造型和动作内容，但允许为统一节奏调整时序。

## 当前资源与播放合约

- 透明 PNG：72×44px，菜单栏显示36×22pt，完整15FPS；位置、画布、透明边缘和可辨识轮廓保持稳定。
- 每状态1–150帧，保留150接受/151拒绝的边界测试；不得任意截段、跳帧或降低FPS绕过上限。
- 独立 Core Animation 播放当前角色/状态；不逐帧替换 status button 图片，不增加常驻面部 Timer 或网页运行时。面板展开时仅可见列表行播放，关闭或滚出可见区域即停止并释放播放帧；减少动态效果使用静帧。
- 导出完整主周期，呼吸、面部及相关附件时间轴闭合；A/B轮换的素材须包含两轮。检查末帧→首帧，接缝不能额外换脸。
- 源动作只在本地适配层改造，保留第三方源与许可。角色制作不修改业务状态聚合、账号、用户配置或 hooks。

## 内置角色时间轴

| 状态 | Grok | Clawd | 面部规则 |
| --- | --- | --- | --- |
| 待机02 | 4秒/60帧 | 4秒/60帧，伸展双爪＋眨眼 | 中性保持；有眨眼时每4秒一次，无连续双眨 |
| 思考30 | 每轮4秒；A/B共8秒/120帧 | 每轮4秒；托腮左右思考共8秒/120帧 | 一次主动作内保持；符号不随机轮播 |
| 工作32 | 每轮4秒；A/B共8秒/120帧 | 每轮4秒/60帧；轻微起伏，右上 + → − → × → ÷ 每秒切换 | Grok 每4秒轮界换脸；Clawd 保持稳定表情 |
| 等待35 | 4秒/60帧 | 4秒/60帧，2×2短方爪招手后停留 | 提示脸保持；身体与附件完成完整动作 |
| 待确认11 | 4秒/60帧 | 4秒/60帧，歪头察看问号 | 保持可辨认面部，不额外闪脸 |
| 完成33 | 2.2秒/33帧 | 2.2秒/33帧，挺身轻抬2×2短方爪 | 单次庆祝，完成脸保持 |
| 错误34 | 1秒/15帧 | 1秒后缩收爪＋4秒叹气尾段，右上固定红×；75帧，loopStartFrame=15 | 入场一次后保持表情；按包定格或循环尾段 |

新角色沿用同一时间轴。打字等必要小动作可以是主节拍的整数细分，但不驱动面部切换。无双表情/左右动作的素材只需一轮，不为凑8秒重复存储。

完成/错误采用核心枚举既有2.2秒/1秒时长，不延迟真实状态。错误状态可选“入场一次＋循环尾段”：如75帧、`loopStartFrame=15`、`staticFrame=15` 表示1秒入场后循环4秒呼吸；相同状态刷新、隐藏恢复与减少动态效果恢复都不重播入场，真实状态更新立即中断，旧入场回调受 generation 保护。该字段仅允许循环状态使用，范围1至frames-1。

## 可核验的交付

- `Scripts/test_unified_cadence.cjs`：所有源码角色七状态的主动作时长、素材时长、完整三轮源动画与两次接缝闭合。
- `Scripts/test_role_cadence.cjs`：复用导出器的真实HTML与时钟，三个完整素材循环，轮内面部保持、边界切换、同状态相位保持及轮内等待切入。
- `Scripts/test_grok_ball_reference.cjs`：完成/错误仍与原版30秒/60Hz逐SVG等价；循环状态改测面部、身体与接缝，不再要求原版随机时间轴等价。
- 资源、原生播放、状态事件与真实菜单栏性能检查入口见技能项目参考。普通窗口、源动画测试、GPU转交渲染服务均不替代实际菜单栏/整机能耗验收。

未完成：小时级泄漏、睡眠唤醒、多显示器/缩放与整机能耗验收。现有Intel次屏角色的限制保持披露。

## 新角色接入

运行时只使用 PNG＋manifest，角色目录自动发现，不新增角色枚举。用户目录、JSON 格式、开发期 `export.json` 协议及本机私有角色见 [角色资源包](character-packs.md)。通用资源校验与源时序测试自动发现新的资源包或源配置；新角色若有独特的脸形/动作，另加针对性回归测试。

Clawd 当前采用11×7矩形躯干、6单位眼距与 `#DE886D` 配色；几何参考及 MIT 许可见 `Resources/Clawd/SOURCE.txt` 和 `LICENSE`。七状态共用母版，工作轻微起伏、固定表情，右上运算符每秒顺序切换，等待与完成保持母模型2×2短爪，不拉长手臂；错误右上5×5加粗像素红×保持稳定且只在错误状态显示。

Clawd 循环主体与肢体采用连续线性插值，避免每个关键姿态反复减速及轮尾重复零姿态；保持15FPS和既有完整周期。完成/错误仍保留缓入缓出与业务停留。`Scripts/test_clawd_actions.cjs` 同时保护循环插值和导出帧不出现超过200ms的连续相同帧（含接缝）；工作状态单独校验4秒运算符序列、固定表情及跨循环接缝。
