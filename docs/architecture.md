# Upkin — 技术说明

## 轻量运行边界

Swift + AppKit 应用；动画使用 AppKit 播放离线导出的透明 PNG 帧，没有 Electron、额外 HTTP 服务、Dots 渲染器、WASM、头像缓存或外观同步。不再提供旧灵动岛、显示器选择或空设置页。

一个 FSEvents 监听器处理登录态、数据库/WAL、索引并发现会话日志；日志再通过原生 vnode 写入监听捕获持续打开文件的追加写入，避免等到写入方关闭文件才更新。启动和恢复扫描覆盖今昨两天目录及其他日期目录中最近 48 小时更新的日志，新文件随事件接入，恢复扫描释放过期监听，替换或删除时释放旧监听，退出时全部释放；日志按文件增量读取。每 10 分钟做一次恢复检查，没有每秒状态轮询。Codex 额度在启动、账号变化、任务完成或手动刷新时通过本地 app-server 查询，请求完成退出子进程；旧账号响应不会覆盖新账号。

会话状态代表本机近期事件汇总，不是当前选中的聊天，也不是进程存活证明。默认不安装 hooks、不修改 AI 工具配置、不删除用户缓存。

## 会话面板

点击菜单栏打开 400pt 原生 AppKit popover：14pt 标题、11pt 分组，按待处理 / 运行中 / 已完成排列。每行有仅在可见时播放的角色状态图标、13pt 标题和 11pt 灰色项目名，不重复堆叠状态文字；悬停和辅助功能标签包含精确状态、来源与完整路径。超过 360pt 的列表滚动，额度区固定在列表外。再次点击、外部点击或 Escape 关闭；右上角齿轮直接打开 700×430pt 原生设置窗口，提供连接、角色、通知、关于四页，无启动引导或活动设置项。

底部按 Codex / Claude / Grok 展示真实额度，可独立展开窗口进度、重置时间与更新时间；未收到任何活动或额度数据的来源整组隐藏。读取失败不伪造额度；刷新同时更新额度和状态。运行时长按本轮开始事件计算，不按最近工具调用计时；不足一分钟、分钟、小时分级显示。面板打开时每 30 秒仅更新时长文本，关闭停止；缺少开始时间不猜测。

桌面来源的 Codex 会话点击后打开 Codex 桌面应用；其余 Codex 会话在 iTerm 中继续：优先定位带会话标记或执行对应 `codex resume` 的标签页，否则在项目目录新建标签页执行 `codex resume --no-daemon <ID>`。首次需系统自动化许可，另需安装 iTerm 和 Codex CLI。未经标记直接以 `codex` 启动的旧标签页暂不匹配；Claude / Grok 使用同样的定位流程，以 `--resume <ID>` 恢复会话。避免桌面与终端同时操作同一会话。

## 元数据读取范围

- Codex 从 JSONL 的 `session_meta` 读取 ID / cwd；优先使用只读 `state_*.sqlite` 的桌面 `name`，缺失时用 `session_index.jsonl` 标题。不用可能包含整段提示词的 `title` 列。发现范围为今日/昨日目录及其他日期目录中最近 48 小时更新的日志；仅最近一小时更新的日志参与活动判定，并非全部历史。
- Claude 从日志头尾读取 `customTitle` / `aiTitle` 和 cwd；Grok 从 `summary.json` 读取 `generated_title` 和工作目录。不用提示词或回复生成标题，不因日志存在就猜测会话正在运行。
- 无标题的 CLI 任务显示“Codex 命令行任务”；子代理显示其名字；内部 `Codex Companion Task:` 包装标题收敛为“Codex 辅助任务”；其余显示“未命名会话”。缺 cwd 时省略项目，长字段截断并可悬停查看。
- 有界读取：日志头尾各 64 KiB、Grok 摘要 64 KiB、Codex 标题索引最多 8 MiB。超出范围保留缺失，不扫描整段聊天或修改源文件。
- 仅明确的开始、工具调用、输入请求、完成和中止事件判定状态，中止不等于成功；同一会话保留最新状态，待机不列入动态列表，不确定与错误归入待处理。

## 额度与认证

### Codex

统一使用 `codex` CLI，优先查找 PATH、`~/.local/bin` 及常见安装目录，再查找 `/Applications` 或 `~/Applications` 中 Codex / ChatGPT 桌面应用内置的 CLI；通过本地 app-server/RPC 读取五小时和每周额度、重置倒计时及更新时间；失败保留上次数据。不会因刷新 token 而误判为切换账号。

### Claude Code

额度读取默认关闭，由用户点击「连接 Claude 额度」并确认用途后开启。通过 Security API 复用钥匙串 `Claude Code-credentials`，条目不存在时读默认 `~/.claude/.credentials.json`。用户主动连接允许系统授权交互；后台及普通刷新使用禁止交互的 `LAContext`，并在串行钥匙串读取期间临时关闭、随后恢复进程级授权交互，需要授权时停止连接并显示重连入口。凭据仅在内存使用，不记录、不缓存、不自动刷新令牌、不修改条目 ACL。读取在后台执行，不阻塞菜单。用户可以在设置的连接页断开连接，停止后续凭据读取，不删除 Claude Code 凭据。

只向 `https://api.anthropic.com/api/oauth/usage` 发只读额度请求，不发送会话内容，重定向不携带 bearer token。启动、手动刷新及每十分钟恢复检查触发额度读取；同账号成功结果在内存缓存 15 分钟，并合并并发请求。接口暂时失败时可继续使用旧数据；429 按 Retry-After 冷却，冷却时间以凭据指纹关联持久化，不保存令牌或额度正文。账号变化、凭据失效或需要重新登录时清理旧数据。仅支持默认 Claude 配置目录和订阅 OAuth 登录，API Key / 第三方网关没有订阅额度。

### Grok Build

复用已登录本机 CLI，优先 `~/.grok/bin/grok`；初始化 ACP，查询 `_x.ai/billing`，不创建会话、不发送提示词、不直接读取或记录令牌。CLI 自行处理网络和认证，应用不修改配置。按真实周/月周期显示进度和重置时间；失败清空旧额度，提示错误，不影响其他来源。私有 ACP 扩展可能随 CLI 版本变化。

## 角色与状态

内置 ChatGPT 角色默认代表 Codex，Grok 角色（源自 Grok Ball）默认代表 Grok Build，原创非官方 Clawd 像素演绎默认代表 Claude Code；菜单栏与会话列表共用同一工具默认角色解析，设置中的角色点击仅预览，不读取或保存自选绑定。菜单栏固定一个图标位，不汇总状态优先级：平时展示非子代理运行任务中 `turnStartedAt` 最新者的角色与 thinking/working 动作；新用户指令或等待后恢复执行刷新轮次时间。焦点停止运行时重选；没有运行任务则保留最后角色待机。

完成与等待事件各提示一次，时长按 manifest 的帧数 ÷ fps 读取，完整播放、不被新任务打断。期间分别保留最新等待和最新完成；播前先校验等待，失效再校验完成，只选一个提示后清空待播槽。每个事件独立发通知，不因跳过动画漏发；首次读取、子代理、中断与错误不发提示。存在等待任务时显示独立静态小点，离开等待时清除对应等待通知。面板仍保留各任务状态、排序与分组。

角色节奏与新角色验收遵守 [角色动画设计规范](character-animation-guidelines.md)。该规范是目标基线，现有素材的符合情况见规范末尾，不将已有播放器测试视为设计验收。

运行时不创建 WebKit。`Resources/CharacterFrames` 保存按现有 SVG/JS 宿主页离线导出的 72×44px 透明帧，在菜单栏以 36×22pt 绘制。一个原生播放器只解码当前角色/状态，切换时释放旧帧。独立 `CALayer` 一次提交完整 `CAKeyframeAnimation(contents)`，离散播放全部 15 FPS 素材帧；主线程没有逐帧 Timer，不以跳帧换取低 CPU。菜单栏完成/等待提示播完回到焦点任务或待机；面板状态预览按 manifest 循环、入场后循环尾段或单次定格；隐藏、宿主不可见或系统减少动态效果时移除动画。

静态角色与额度位图只在状态、等待标记的有无、额度、外观或缩放变化时更新，避免逐帧触发 NSStatusItem 的其他屏幕副本快照。参考 RunCat Neo 的做法，Apple Silicon 上通过独立 source-out 背景层清除当前屏幕角色静态副本，保留其他屏幕静态回退；清除区域仅宽 32pt，额度区域不受影响。Intel 使用不含角色的静态底图，角色仅由活动屏幕动画层绘制，因此其他屏幕可能只显示额度。没有引入新运行时依赖；引用及许可随包保留。素材缺失或损坏时使用原生终端图标回退。

菜单栏角色按提供方选择角色包：使用 manifest `defaultFor` 声明（可为单个 ID 或数组），最后回退到排序第一的角色包；不读取旧的用户自选绑定。

列表先显示代表帧，再在后台解码可见行的状态帧，同状态共享解码结果，复用原生播放器；滚出可见区或关闭时释放播放帧。没有截图轮询或逐帧计时器。离线预制保留角色和主要动作，但随机眨眼、实时鼠标跟随变为固定循环；不是逐帧实时引擎的完全等价替代。

### Grok 角色（Grok Ball）

离线导出固定使用 `de368ce3acdc5a70e871ee46ebbe8f60b11d3d6a` 原始 JS，见 `ThirdParty/GrokBall`。宿主页仅做透明背景、22pt 等比布局与状态入口。默认眼睛比例为 1，主体左对齐 26pt 区域；角色轮廓与原始眼环保留；本地适配层将循环状态变为 4 秒完整轻摇/呼吸，工作与思考每轮只换一组眼环，A/B 两轮导出为 8 秒。待机、等待、未知保持原始代表脸；取消独立随机眼神和双眨。思考彩带改为保持原细彩带外观的确定性闭合轨道。原版 JS 和注册配置不修改，完成/错误仍验证与原版等价。菜单栏只为完成/等待事件播放一个 manifest 完整周期；错误仅保留在面板，不触发菜单栏提示。工作与思考跟随焦点任务，等待标记独立保留。上游完整配置保留原样，但应用不开放其他角色/表情。

原始 JS 保留供重新导出，不加入运行时动画路径。系统减少动态效果时显示静帧。许可与固定版本详见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

### Clawd

`Resources/Clawd/index.html` 为独立绘制的像素 SVG/CSS 源，七状态沿用统一节拍；思考为8秒 A/B，工作为4秒固定表情与右上运算符轮播，完成2.2秒，错误为1秒入场＋4秒循环尾段（`loopStartFrame=15`）。本地绘图适配与动画采用 AGPL-3.0，参考的 clawd-pet 像素几何保留 MIT 署名；Clawd 角色与商标归 Anthropic，本演绎非官方，不授予角色权利。

## 额外验证

基本及界面检查见 [贡献指南](../CONTRIBUTING.md)。上游逐帧对照需 Node、Playwright 和本机 Chrome，运行应用不依赖这些开发工具：

```bash
NODE_PATH=/path/to/installed/node_modules node Scripts/test_grok_ball_reference.cjs
```

来源测试对完成/错误保留 30 秒、60Hz 的原版 SVG 等价检查；循环状态属于有意的节奏适配，检查完整周期的面部保持、身体运动与接缝，不再声称与原版随机时间轴逐帧等价。`Scripts/test_role_cadence.cjs` 复用导出的时钟与 HTML，覆盖三个完整资源循环、相同状态相位保持及轮内等待切入。原生测试另验证 PNG、帧释放、可见性与单次定格。

可选真实账号检查（不属于默认测试，不输出凭据）：

```bash
swift run UpkinCoreTests --live-sparse-path
swift run UpkinCoreTests --live-claude
swift run UpkinCoreTests --live-grok
```

Hook 事件、时效、安装副作用和撤销见 [活动接入](grok-claude-activity.md)。
